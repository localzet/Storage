# Localzet Storage

[English documentation](README.md)

Клиент-серверное общее хранилище данных для приложений Localzet Server.

## Состояние и совместимость

Текущий выпуск — `2.0.1`. Пакет рассчитан на Localzet Server 7 и исправляет framing клиента при частичном чтении и записи заголовка или тела кадра. В версии 2 изменился контракт payload по умолчанию: объекты и рекурсивные массивы отклоняются, скаляры и ациклические массивы поддерживаются. В версии 2.0.1 структура payload ограниченно проверяется до декодирования. Перед обновлением проверьте клиентов 1.x, которые отправляют PHP-объекты.

Транспорт использует PHP serialization с length-prefixed кадрами (payload до 64 МиБ плюс 4-байтовый заголовок). Storage задаёт лимит полного кадра отдельно для каждого соединения, не меняя общие настройки Server. Учитывайте память, которую могут одновременно занять крупные кадры. В безопасном режиме проверка отклоняет значения, содержащие суммарно более 100 000 элементов массивов, а также вложенность глубже 128 уровней. Порты должны оставаться в доверенной сети. Хранилище работает только в памяти одного процесса: в нём нет персистентности, репликации, аутентификации клиентов и контроля конкурентных операций.

Компонент требует Server 7.2.3 или новее в пределах версии 7. По умолчанию сервер слушает loopback; встроенной аутентификации клиентов нет. Используйте его только в доверенной сети, а для привязки к внешнему интерфейсу заранее настройте сетевой контроль доступа. При выключенной поддержке объектов сервер и клиент отклоняют PHP-объекты, включая `__PHP_Incomplete_Class`, рекурсивные массивы, массивы с суммарно более 100 000 значениями и массивы глубже 128 уровней. Для доверенной изолированной сети включайте сериализацию объектов явно на обеих сторонах: `new Server($ip, $port, allowObjectSerialization: true)` и `new Client($servers, allowObjectSerialization: true)`. Этот opt-in возвращает прежнее поведение PHP-сериализации и отключает эти ограничения проверки; никогда не включайте его для недоверенных клиентов.

### Переход с 1.x

Перед обновлением удалите PHP-объекты и рекурсивные массивы из значений хранилища. Если их необходимо сохранить, включите сериализацию объектов на сервере и клиенте и оставьте соединение в доверенной изолированной сети. Ветка 1.x уже рассчитана на Server 7; с Server 4 она несовместима.

## Зависимости

- `php`: `^8.2`
- `localzet/server`: `^7.2.3`

## Установка

```sh
composer config repositories.localzet-storage vcs https://github.com/localzet/Storage
composer require localzet/storage:^2.0
```

Пакет пока не опубликован в Packagist; Composer получает стабильные теги `2.x` из указанного VCS source.

## Быстрый запуск

Запустите сервер хранилища в отдельном CLI-процессе:

```php
<?php

use localzet\Server;
use localzet\Storage\Server as StorageServer;

new StorageServer('127.0.0.1', 8008);
Server::runAll();
```

Подключитесь к нему из приложения:

```php
<?php

use localzet\Storage\Client;

$storage = new Client('127.0.0.1:8008');
$storage->set('greeting', 'hello');
$greeting = $storage->get('greeting');
```

Обе стороны должны использовать совместимую framing-модель Server 7. По умолчанию PHP-сериализация принимает только скаляры и ациклические массивы; включайте constructor opt-in, только если доверяете каждому узлу.
